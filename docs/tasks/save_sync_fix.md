# GPT 작업 지시서 — 드라이브 저장 동기화 안정화 (문플로 방식으로 되돌리기)

시작 전: `AGENTS.md` → `docs/STATUS.md` → `docs/WORKLOG.md` 맨 아래(특히 10/06 "실시간 저장 원인 분석", "문플로 저장 동기화 기록 대조") 순서로 읽는다.
참고 원본(읽기만): GitHub `Alix1211/moonflo` 의 `android/app/src/main/java/com/moonsunfarm/game/MainActivity.java`(`writeBackup`, `holdBackup`, `checkRemote`)와 `web/js/backup.js`(`onFarmRemote`, `hold`, `syncTs`).

## 한 줄 설명
지금 ARPG의 자동 동기화는 "저장마다 읽기→비교→쓰기"라서 읽기가 늦으면 저장이 안 되고, 낡은 기기가 새 진행을 덮을 수 있다. 문플로가 같은 문제로 고생한 끝에 정착한 구조(쓰기 따로, 읽기 따로, 충돌 시 묻기)로 바꾼다.

## 확정 (케인 결정·사실)
- 구글 로그인/API 키는 쓰지 않는다. 지금처럼 파일 선택(SAF) 방식을 유지한다. 저장 형식(`arpg_save_v3` 등)·서명 열쇠는 바꾸지 않는다.
- 저장은 기기 로컬이 우선이다(오프라인에서도 계속 플레이).
- 케인이 원하는 것: 수동 불러오기에 의존하지 않는 **자동** 동기화.
- 한계(바꿀 수 없음): 드라이브 앱이 파일을 늦게 올리거나 낡은 사본을 읽을 수 있어 진짜 실시간은 불가능하다. 목표는 "다른 기기를 켜는 순간 최신 진행이 이어짐"이다.

## 가안 (케인 확인 대기 — 충돌 시 선택창)
- **충돌(둘 다 바뀜)일 때만** 문플로식 선택창을 띄운다: "다른 기기에서 ○○에 저장한 진행이에요 / 파일: 레벨·금화·시각 / 이 기기: 레벨·금화·시각 / `파일의 진행으로 이어서 하기` · `이 기기 진행으로 파일 덮어쓰기`". 창을 닫으면 다음에 다시 묻고 그동안 파일에는 쓰지 않는다. 케인이 "선택창 없이 완전 자동"을 원하면 그때 바꾼다.

## 고칠 것 (원인 → 처방)
1. **저장 때 읽기 금지.** 5초 저장 묶음은 **쓰기만** 한다(읽기 선행·비교 없음). 쓰기 간격은 상수(처음 15~30초, 앱이 내려갈 때는 즉시 1회). 읽기는 **앱 시작/복귀/온라인 복귀** 때만, 짧은 간격 제한(예: 20초)을 둔다. 신호 세기 변화마다 동기화가 새로 시작되지 않게 네트워크 콜백을 줄인다(연결 상태가 "없음→있음"으로 바뀔 때만).
2. **비교 기준을 "마지막으로 맞춘 버전"으로.** 이 기기에 `syncBase`(마지막으로 파일과 맞춘 저장의 진행 값)를 저장한다. 판정:
   - 파일만 바뀜(파일 > base, 이 기기 = base) → 자동으로 가져와 적용.
   - 이 기기만 바뀜(이 기기 > base, 파일 = base) → 파일에 쓰기.
   - 둘 다 바뀜 → 선택창(가안).
   - 기기 시계끼리 겨루지 않는다.
3. **진행이 바뀔 때만 버전이 올라가게.** 지금은 앱을 켰다 끄기만 해도(`onPause`의 `UI.save`) `t`가 최신이 되어 새 진행을 덮을 수 있다. 저장 값이 실제로 바뀐 경우에만 `t`(또는 진행 카운터)를 갱신한다. 기존 저장에는 호환되게(`t`만 있는 옛 저장도 읽힘).
4. **깨진 파일 자가 복구.** 파일이 비었거나 형식이 틀리면(새 파일이 아니어도) 이 기기의 유효한 저장으로 덮어써 복구한다. 이때만 한 번 "파일이 깨져 있어 이 기기 저장으로 복구했습니다"를 표시한다.
5. **쓰기를 중간에 취소하지 않는다.** 6초 제한 후 `cancel(true)`로 `"wt"` 쓰기를 끊으면 끊긴 파일이 생긴다. 시간 제한은 "화면에 대기 표시를 풀기"에만 쓰고, 쓰기 자체는 끝까지 둔다. 가능하면 이 기기에서 쓴 직후 길이를 확인해 실패를 알린다.
6. **타임아웃 정렬.** JS의 8초 해제와 네이티브 읽기/쓰기 시간을 맞춘다. 동기화가 화면 진행을 멈추지 않는 현재 동작(전체화면 덮개 없음, `ARPG_SYNC_DIRTY`로 한 번만 재저장)은 유지한다.
7. **상태 표시.** 설정창 한 줄에 `연결됨 · 마지막 올림 · 마지막 맞춤`과, 실패 시 이유를 한 문장으로(오프라인 / 읽기 실패 / 파일 깨짐 / 충돌 대기) 보여 준다. 문구는 전연령.

## 검사
`tools/check_save_sync.js`, `src/town/check_backup.py`, Android 단위 검사(`BackupValidationTest`)를 새 규칙에 맞게 고치고 아래를 확인한다.
① 저장 중 읽기가 일어나지 않는다(읽기 실패/지연에도 쓰기는 된다). ② 파일만/이 기기만/둘 다 바뀜 3가지 판정. ③ 앱을 켰다 꺼도 버전이 오르지 않는다. ④ 빈 파일·깨진 파일이 이 기기 저장으로 복구된다. ⑤ 쓰기 취소로 끊긴 파일이 생기지 않는다. ⑥ 오프라인 플레이 후 온라인 복귀 시 위 판정대로 동작. ⑦ 옛 저장(`syncBase` 없음, `t`만 있음) 호환. ⑧ 오류 0.
**검사 파일을 고쳤다면 푸시 전에 로컬에서 먼저 실행한다**(깨진 검사 파일로 빌드가 막힌 적이 있다).
