# 표준: 구글 드라이브 저장 동기화 (케인의 모든 웹앱→안드로이드 앱 공통)

케인이 고정한 표준이다. 문플로와 ARPG에서 같은 오류로 몇 시간씩 허비해서 만들었다. **이 규칙을 바꾸거나 "더 똑똑하게" 고치지 말 것.** 바꿀 필요가 있으면 먼저 케인에게 묻는다.
참조 구현: ARPG `android/app/src/main/java/com/alix/arpg/MainActivity.java`(`decide`, `requestSync`, `writeBackup`, `resolveConflict`, `parseRemote`, `writeDocument`)과 `src/town/backup.js`(`onArpgSyncConflict`), `src/town/save_sync.js`.

## 방식
- 구글 로그인/API 키 없이 파일 선택(SAF)으로 드라이브 파일 하나를 고른다(`ACTION_CREATE_DOCUMENT`/`ACTION_OPEN_DOCUMENT` + 읽기·쓰기 영구 권한).
- **한계(바꿀 수 없음):** 진짜 실시간이 아니다. 드라이브 앱이 늦게 올리거나 낡은 사본을 줄 수 있다. 목표는 "한쪽을 끄고 다른 쪽을 켜면 이어진다"이다.
- 저장은 기기 안이 우선(오프라인에서도 계속 플레이). 드라이브는 맞추는 곳.

## 절대 규칙
1. **저장 시각끼리 겨루지 않는다.** 게임은 켜져 있기만 해도 자동 저장으로 시각이 최신이 된다. "늦게 저장한 쪽이 최신"으로 고르면 진행이 적은 기기가 켜자마자 다른 기기 진행을 덮어쓴다(문플로·ARPG 모두 이 원인).
2. **기준은 "이 기기가 파일과 마지막으로 맞춘 버전"(baseT).** 기기 설정에 저장한다. `lt`=이 기기 저장, `rt`=파일 저장(없거나 깨지면 -1), `bt`=baseT(모르면 -1):
   - 파일 없음/깨짐 → 이 기기 저장으로 채움(이 기기에도 없으면 아무것도 안 함)
   - 이 기기에 저장 없음 → 파일을 가져옴
   - `lt == rt` → 그대로
   - 파일만 바뀜(`rt > bt`, `lt <= bt`) → 자동으로 가져옴
   - 이 기기만 바뀜(`lt > bt`, `rt <= bt`) → 자동으로 올림
   - 둘 다 바뀜, 또는 기준을 모름 → **선택창으로 묻는다**
   - 맞춘 뒤(가져옴/올림/같음/선택) 반드시 baseT를 갱신한다. 새 파일을 연결하면 baseT = -1.
3. **선택창(문플로 방식):** 드라이브 쪽과 이 기기 쪽의 핵심 진행(레벨·금화·저장 시각 등)을 나란히 보여 주고 `드라이브 진행으로 이어서 하기` / `이 기기 진행으로 파일 덮어쓰기` 두 버튼, 확인 한 번. **고르는 동안 파일 쓰기와 게임 저장을 모두 막는다.** 창을 닫거나 앱을 끄면 다음에 다시 묻는다.
4. **저장할 때는 쓰기만 한다.** 읽기→비교→쓰기를 저장마다 하지 않는다(읽기가 늦으면 저장이 통째로 막힌다). 읽기는 앱 시작·복귀·온라인 복귀·`지금 동기화` 때만. 이번 실행에서 아직 파일을 읽어 맞추지 못했으면 쓰기 전에 먼저 읽어 맞춘다.
5. **쓰기를 중간에 취소하지 않는다.** `"wt"`로 비운 뒤 끊으면 끊긴 파일이 남는다. 시간 제한은 화면 표시용으로만 쓴다.
6. **빈 파일·깨진 파일은 이 기기의 유효한 저장으로 덮어써 복구한다.** 단, 읽기 자체가 실패(통신 등)하면 파일을 건드리지 않는다.
7. **불러오기(파일 적용) 직전·도중에는 자동 저장을 막는다.** 다시 시작하기 직전의 자동 저장이 불러온 진행을 덮어쓴 적이 있다(문플로).
8. **화면 쪽 저장 막기 대기시간은 앱 쪽 읽기 대기시간보다 길게.** (ARPG: 앱 읽기 15초, 화면 20초.) 짧으면 읽는 도중 자동 저장이 풀려 시각만 최신이 된다.
9. 동기화 중에 생긴 저장은 버리지 말고 끝난 뒤 한 번 다시 올린다.
10. 저장 파일 형식은 앱마다 그대로 두고 묶음째 올린다. 형식 변환·시각 다시 쓰기 금지.

## 검사 (새 앱에 붙일 때 필수)
- `decide` 단위 검사: 처음 맞춤(bt=-1)에서 시각이 늦은 쪽이 이기지 않고 묻는지, 파일만/이 기기만/둘 다 바뀜, 같음, 파일 없음/깨짐, 이 기기 저장 없음.
- 깨진·빈·끊긴 파일이 복구 대상으로 판정되는지.
- 선택창: 표시 내용, 취소 시 아무것도 안 함, 확정 시 해당 동작, 고르는 동안 저장 막힘.

## 문제가 생겼을 때 (AI가 할 일)
- **케인에게 같은 확인 절차를 반복시키지 않는다.** 먼저 드라이브 기록을 직접 본다(Claude는 Google Drive 커넥터로 파일 목록·수정 시각·크기·내용의 레벨/금화를 확인). 어느 기기가 언제 무엇을 썼는지 확인한 뒤 원인을 말한다.
- 흔한 원인: 저장 시각 경쟁(규칙 1 위반), 기기마다 다른 파일(같은 이름 파일이 따로 생김 — 두 번째 기기는 `기존 파일 연결`), 다른 구글 계정, 드라이브 앱 로그아웃, 옛 앱 설치(새 앱 덮어 설치 필요).

## 케인용 복구 절차 (문플로 때 정착)
1. 진행이 많은 기기 말고 다른 기기는 앱을 끈다.
2. 진행이 많은 기기에서 새 저장 파일을 만든다(또는 선택창에서 `이 기기 진행으로 파일 덮어쓰기`). 홈으로 보낸다.
3. 다른 기기에 새 앱을 덮어 설치한 뒤 켜서 `기존 파일 연결`로 그 파일을 고르거나 선택창에서 `드라이브 진행으로 이어서 하기`.
4. 예전 저장 파일은 지운다.
